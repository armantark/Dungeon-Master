1. Start here

Natural 90-second opening
Architecture thesis

The model proposes semantics and prose. Python validates, orders, resolves, and commits.

Persisted game state is canon. Derived memory and browser state can be rebuilt or replaced.

Speaking prompts
  • I ran solo campaigns in ChatGPT. Old details disappeared or contradicted later turns.
  • I built a local game system that keeps campaign canon outside the model context.
  • Specialized calls interpret actions, propose updates, and write narration.
  • Python owns Cairn-inspired mechanics, validation, order, cancellation, and canonical commits.
  • The result is creative model output inside a deterministic, inspectable state machine.

4. Three consequential decisions

Problem → choice → trade-off → change trigger
Decision 1

Deterministic Python skeleton

Problem
One unconstrained model can mix rules, prose, state changes, and hidden assumptions.
Chosen design
Typed model proposals run inside a Python-owned pipeline.
Why proportionate
The game needs creativity, but it also needs repeatable mechanics and inspectable canon.
Cost
More orchestration code and more role boundaries.
Change when
A simpler model workflow matches correctness on a fixed campaign corpus.
Decision 2

JSON persistence for the local prototype

Problem
The prototype needed durable, readable local saves without service operations.
Chosen design
Use JSON state, append-only events, checkpoints, and a derived memory sidecar.
Why proportionate
One local player has low write contention and benefits from direct inspection.
Cost
No atomic transaction across the related files.
Change when
Crash recovery, concurrent writes, or history queries become product requirements.
Decision 3

Bounded derived memory

Problem
A full transcript grows without bound and can carry obsolete details forward.
Chosen design
Rebuild bounded narrator context from committed turns and linked checkpoints.
Why proportionate
The local corpus is structured and chronological. Exact current canon matters more than semantic search.
Cost
Compression can omit useful color and requires careful derivation.
Change when
A measured retrieval corpus proves that semantic retrieval improves continuity without stale-context regressions.

5. Persistence evolution

Use the smallest store that meets the actual operating model.
Current · local

JSON is acceptable

Files are readable and easy to inspect. Each file uses a temporary file and replace operation. One player creates little contention.

Weakness: the full save is not one transaction. A crash can leave events or checkpoints ahead of game_state.json.

Likely next

SQLite

Use atomic transactions, crash recovery, queryable history, and serialized writes in one local database.

Keep revision numbers in the application schema. SQLite gives transactions. It does not create revision semantics.

Only with a product trigger

Postgres

Use Postgres for remote hosting, accounts, or multiplayer. Do not add network operations before those needs exist.

The database choice follows the concurrency and deployment model.

6. Difficult failure: the obsolete chapel

Verified in commit d48eca8
Symptom

Narration kept referring to leaving the chapel after the character had already left.

Cause

Stale derived memory and an over-broad scene summary leaked obsolete context into the narrator prompt.

Investigation

Compare committed turns, linked checkpoints, canonical game state, and the exact narrator context. This separates bad canon from bad derivation.

Fixes

Rebuild context from checkpoint-linked committed turns. Prefer the canonical current scene. Pass the deferred checkpoint override into streamed narration.

Proof

The regression injects obsolete chapel text into the sidecar. It asserts that the next narrator context excludes it and includes checkpoint-linked turn material.

Lesson

Derived context must never outrank canonical state. Treat memory as a cache with provenance, not as an independent truth source.

7. Limitations and next steps

All items below are future work, not current behavior.

Reliability and scale

  • Move related save writes into SQLite transactions.
  • Add accounts and authentication before multiplayer.
  • Add idempotency keys and queued turns if asynchronous play needs them.

Evidence before more architecture

  • Evaluate model roles on a fixed campaign corpus.
  • Use a separate prose model only if the evaluation proves a gain.
  • Do a rules-chassis comparison audit.
  • Do an emergence and simplification audit.

8. Principal-engineer interruptions

Open a prompt for a ~30-second answer anchor.
Why not one smart model?

One call couples interpretation, mechanics, mutation, and prose. Typed roles make failures local. Python still enforces the final contract.

Why is Python authoritative?

Rules and state changes need repeatability, validation, and tests. The model proposes meaning. Python owns irreversible decisions.

What exactly is canon?

The persisted GameState is current canon. Committed events and checkpoints provide history. Derived memory and browser state cannot override it.

Why JSON?

It matched one local player, low contention, and direct inspection. It reduced operating work while the product shape changed.

Why SQLite next?

SQLite keeps local deployment while adding atomic multi-record commits, crash recovery, serialized writes, and queryable history.

Why replace complete client state?

The server owns truth. Full replacement avoids a second reconciliation system and prevents client patches from drifting from canonical state.

What is memory.json?

It is a bounded, derived narrator-context sidecar. The service rebuilds it from canonical state, committed turns, and linked checkpoints.

Why not retrieval-augmented generation?

The current corpus is local, ordered, and structured. Retrieval adds indexing and stale-result failure modes before measured need exists.

What happens on turn cancel?

The client asks the server to cancel, clears provisional output, then aborts locally. Before persistence, tests prove canonical state stays unchanged.

What failed in production-like use?

Stale memory made narration reuse an obsolete chapel scene. The fix made checkpoint-linked committed turns and current canonical state authoritative.

What comes next?

First, SQLite transactions. Then measure model roles and rules choices on fixed corpora before adding more model or retrieval architecture.

How would this support multiplayer?

Add identity and authorization first. Then add transactional writes, revision checks, idempotency, queued turns, and a clear concurrency policy.
